# 推し活手帳（OSHIKATSU DIARY）

推し活（アイドル・アーティストのファン活動）を記録するための個人用Webアプリです。
LIVE参戦・チェキ・物販の記録、複数推し・複数グループ（兼任）の管理、統計表示などができます。

## 実行方法

ビルド不要の単一HTMLファイルです。

```bash
open index.html   # または任意のブラウザで直接開く
```

ローカルサーバーも不要ですが、使う場合は例えば：

```bash
npx serve .
# または
python3 -m http.server 8000
```

## クラウド同期（Supabase）とログイン

**ログイン必須**です。未ログイン時はログイン画面だけを表示し、タブ・＋ボタン・ヘッダーの操作は隠します（`render()` の先頭で `renderAuthGate()` に切り替え、`#app.auth-gate` のCSSで非表示）。ログインすると記録が Supabase に保存され、複数の端末で同期されます。接続情報を取得できない場合（`index.html` をファイルとして直接開いた場合を含む）は、接続できない旨と再読み込みボタンを表示します。

右下の＋ボタン（記録の追加）は、押したまま動かすと好きな位置に置ける（`bindFabDrag`）。8px以上動かすとドラッグになり、動かさずに離すとこれまでどおり追加の画面を開く。位置は画面に対する割合で端末に保存し（`localStorage` の `oshikatsu_fab_pos`。端末ごと・同期しない）、画面の大きさが変わっても画面内（下のタブより上）に収める。一覧の最後のカードが＋ボタンに隠れないよう、ページの下に余白を取っている。

- **ログイン方法**：メールアドレス＋パスワード（新規登録・パスワード再設定あり）、Googleアカウント
- **接続情報**：`api/config.js`（Vercel Serverless Function）が、Vercel の環境変数 `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY`（または `..._PUBLISHABLE_KEY`）を `/api/config` で返します。service_role / secret キーは返さないようにしています。
- **ライブラリ**：`vendor/supabase-js-2.117.2.js`（@supabase/supabase-js の UMD 版を同梱。CDN には依存しません）
- **テーブル**：`supabase/migrations/20260925000000_create_oshikatsu_records.sql`
  - `oshikatsu_records(user_id, kind, id, data jsonb, deleted, created_at, updated_at)`
  - `kind` は `oshi` / `live` / `cheki` / `goods` / `settings`。1件の推し・記録・設定が1行です。
  - RLS により、本人の行しか読み書きできません。削除は `deleted=true` の論理削除で、ほかの端末にも反映されます。

### 同期の仕組み

- 端末側は、ユーザーごとのキャッシュ（`oshikatsu_diary_v1:u:<userId>`）と同期メタ情報（`oshikatsu_sync_v1:<userId>`）を `localStorage` に持ちます。
- `saveLocal()` が呼ばれると、「最後にクラウドと一致していた内容のハッシュ」と比べて、変更・追加・削除された行だけを送信します（0.8秒のデバウンス）。
- 受信は `updated_at` による差分取得です。画面に戻ったとき、オンラインに復帰したとき、開いている間は20秒ごとに自動で行います（同期状態は画面に表示しません）。
- 同じ行を複数の端末で編集した場合は、後から保存した方が残ります。
- ログイン必須化より前にその端末で付けていた記録（`oshikatsu_diary_v1`）は、ログイン時に確認のうえアカウントへ取り込めます。
- ログアウトすると、その端末のユーザー別キャッシュは削除されます。

### LIVE・物販のカードの高さ

LIVE・物販の一覧のカード（`ticketHtml` の `.ticket.fixed`）は、内容に関係なく同じ高さ（150px）。右側（日付と写真が入る所）はチラシと同じ縦横比（A判・約1:1.41）で、幅は約105px。公演名・推しの行・会場・商品名・メモ・リンクは1行に収め、はみ出す分は「…」で省略する。LIVE のメモは一覧には出ない（編集画面で見る）。チェキは別の表示なので対象外。

### 推しの管理（独立ページ）

右上の推しのドロップダウンの「すべて管理」から開く（`state.view = "oshis"`、`renderOshisPage`）。「＋ 新しい推しを登録」、登録した推しのカード（1人1枚。お気に入り・編集・非表示）、非表示の推しがある。並べ替えはホームのカードと同じく、カードの上のつまみを押したまま上下に動かす（`bindDragReorder` を共通で使う。表示中の推し同士、非表示の推し同士で入れ替わる → `applyOshiOrder`）。このページの右下の＋は推しの登録。マイページには推しの一覧を出さず、「アカウント」と「ログアウト」を置く。

### マイページの「アカウント」

「登録した推し」とプライバシーポリシーのリンクの間に表示します。

- メールアドレス：ログイン中のアカウント
- パスワード：設定済み／未設定と「変更」「設定」ボタン。Googleだけで登録した人も、ここでパスワードを設定するとメールアドレスでログインできます（`sb.auth.updateUser`）。
  - Google で登録した人がパスワードを追加しても Supabase のユーザー情報には現れないため、設定・変更時に `user_metadata.has_password = true` を保存して「設定済み」の判定に使います。すでに同じパスワードがある（Supabase が「前と同じ」と返す）場合も目印だけ付けます。
- Google認証：連携済み／未連携と「連携する」「解除」ボタン（`sb.auth.linkIdentity` / `unlinkIdentity`）。ログイン方法が1つしかない場合は解除できません。
  - 「連携する」を使うには、Supabase の Authentication → Sign In / Providers で **Allow manual linking** を有効にする必要があります。
- ログアウト

### Supabase / Google 側の設定

1. SQL Editor で上記マイグレーションの SQL を実行する（または Supabase の GitHub 連携で適用する）。
2. Authentication → URL Configuration
   - Site URL：`https://oshikatsu-diary.vercel.app`
   - Redirect URLs：`https://oshikatsu-diary.vercel.app/**`（プレビュー環境も使う場合は `https://*-minatani-01s-projects.vercel.app/**` も追加）
3. Authentication → Sign In / Providers → Google を有効にし、Google Cloud Console で発行した OAuth クライアントID・シークレットを登録する。
   - Google 側の「承認済みのリダイレクト URI」には、Supabase の Google 設定画面に表示される Callback URL（`https://<project-ref>.supabase.co/auth/v1/callback`）を登録します。

## 技術構成

- **1ファイル完結**：`index.html` の中にCSS（`<style>`）とJS（`<script>`）がすべて内包されています。ビルドツールは使用していません（vanilla JS / vanilla CSS）。外部ライブラリは同梱の supabase-js のみです。
- **データ保存**：Supabase が正本で、ブラウザの `localStorage` にユーザー別のキャッシュを持ちます（上記参照）。
  - キー: `oshikatsu_diary_v1:u:<userId>`（ログイン中のキャッシュ）、`oshikatsu_diary_v1`（ログイン必須化以前のデータ。初回ログイン時に取り込み可）
  - 中身: `{ oshis, live, cheki, goods, activeOshiId, headerLogo }`
- **画像**：アップロードされた写真はすべて `dataURL`（base64）としてlocalStorageに直接保存されます。ファイルアップロードは `resizeImageFile`（JPEG化・不透明画像用）と `resizeImageFilePreserveAlpha`（PNG化・透過を保持したい画像用、ヘッダーロゴなど）の2種類のリサイズ関数を使い分けています。

## データモデル（概要）

### 推し（oshi）
```
{
  id, name, agency, photo, color, birthYear, birthMonth, birthDay,
  groups: [
    { id, name, color, sns_web, sns_instagram, sns_x, sns_tiktok, sns_youtube }
  ],
  sns_person_instagram, sns_person_x, sns_person_tiktok, sns_person_youtube, sns_person_web,
  photoOriginal, mode: "pale", order, hidden, createdAt
}
```
- プロフィール写真は `AvatarCropper` で丸枠に合わせて切り抜いた 480x480 のJPEGを `photo` に、切り抜く前の画像（長辺1000pxに縮小）を `photoOriginal` に保存する。写真メニューの「位置を調整」で、`photoOriginal` から何度でも調整し直せる（以前に登録した写真は `photo` から調整）。
- `hidden: true` の推しは非表示。推しの切り替え・記録一覧の絞り込み・記録フォームの推し選択に出さない（`visibleOshis()`）。記録や集計には残り、「推しの管理」ページの「非表示の推し」から戻せる。お気に入りの推しを非表示にすると、表示中のほかの推しがお気に入りになる。
- `groups` は配列の**並び順がそのまま「メイン所属／サブ所属」を表す**（先頭＝メイン）。専用のフラグは持たない。
- 推しの登録・編集で、所属（`#agencyOptions`）とグループ名（`#groupNameOptions`）の入力欄には、登録済みの値を `datalist` で候補表示する。グループ名を候補から選んだときも、下のSNS自動入力がその場で働く。
- 推しの登録・編集でグループ名を入力し終えたとき、ほかの推しに**完全一致**する名前のグループがあれば、そのSNS（公式HP含む）を空欄にだけ自動で入れる（同じグループの別メンバーを登録するとき用。入力済みのSNSは上書きしない）。
- 個人の `sns_person_web` とグループの `sns_web` は公式HPのURL（IDではなくURLを保存）。`safeWebUrl()` で http(s) のみに正規化し、スキーム省略時は `https://` を補う。そのほかの `sns_*` はIDを保存する。
- 推し全体のテーマカラー（`oshi.color`）は、保存時に「メイングループの色」から自動的に決定される（`effectiveColor()` 参照）。グループが1つもない推しは自動割り当てのプリセット色になる。
- 過去バージョンの単一グループ形式（`oshi.group` 文字列 + `sns_group_*`）のデータも `oshiGroupsList()` が後方互換で読み込む。

### 記録（live / cheki / goods）
各配列は `state.live` / `state.cheki` / `state.goods` に格納。共通フィールド：
`{ id, oshiId, groupId, date, memo, tag, favorite, hidden, ... }`
（`groupId` はその記録がどのグループ活動かを表す任意フィールド。フォームでは推しを選ぶとメイングループがデフォルト選択される）

- live固有: `title, venue, streamUrl, ticketType, seat, price, photo, extraOshis, openTime, startTime, endTime`
  - `openTime` / `startTime` / `endTime`：開場・開始・終了の時刻（`HH:MM`、任意）。
  - 一覧のLIVEは、推しの行にグループ名だけを出し（同じグループは1回、グループのない推しは人物名）、次の行は会場。チケット種別・座席は一覧に出さない。1行目の右端の「…」ボタン（`live-menu`）を押すとメニュー（`#streamMenu`）が開き、「チケットを見る」（チケットURLがあるとき）、「配信を見る」（配信URLの数だけ。複数なら（1）（2）とドメイン）、「Googleカレンダーに追加」から選ぶ。LIVEタブでは金額（チケット代・合計）を出さない（件数だけ）。
  - 予定のタイトルはマイページのアカウントのカード「Googleカレンダー」の「接続／変更」から開く画面で指定し、「保存」ボタンで保存する（`state.calendarTitle`、設定行 `settings:main` の `calendarTitle` として同期）。`{公演名}` `{グループ}` `{会場}` `{観戦方法}` を組み合わせられ、空欄なら `{公演名}`（`calendarTitleFor()`）。
  - 予定の説明も同じ欄で指定できる（`state.calendarDesc`、設定行の `calendarDesc`）。差し込み項目は `{公演名}` `{グループ}` `{会場}` `{観戦方法}` `{開場}` `{開始}` `{終了}` `{チケットURL}` `{配信URL}`。差し込み項目がすべて空になった行は省く。空欄なら標準の説明（開場・開始・終了・出演・チケット・配信）（`calendarDescFor()`）。
  - 差し込みボタンは「保存」の上に1か所だけあり、最後に触った欄（タイトル／説明）に `{項目}` を入れる。差し込み項目はタイトル・説明とも共通（`calendarTokenValues()`）。表示例は出さない。
  - 「カレンダーに追加」は `googleCalendarUrl()` で Google カレンダーの予定作成URL（APIキー不要）を開く。開始＝開始時刻→開場時刻、終了＝終了時刻→開始の2時間後、時刻が無ければ終日。メモに開場・開始・終了、出演グループ、チケットURL、配信URL（複数なら「配信1」「配信2」…）、場所に会場（住所）を入れる。
  - `viewing`：観戦方法。`"venue"`（現地）/ `"stream"`（配信）/ `"tbd"`（未定）。フォームは日付の下のボタン（現地・配信・未定）で選び、一覧のチケットには「LIVE」の横に現地（塗り）／配信（枠線）／未定（グレー）の印を出す。未定はフォームのボタンのアイコンもグレー。参戦回数・遠征マップに数えるのは現地だけ（配信・未定は数えない）。未設定の以前の記録は、配信URLがあって会場が空なら配信、それ以外は現地とみなす（`recViewing()`）。ホームの「参戦」や集計の「参戦」は現地観戦だけを数える（配信で観たLIVEは数えない）。ホームの「参戦」・集計の「参戦」・遠征マップ（会場・現地参戦の数、ピン、吹き出し）は、今日までに行ったLIVEだけを数え、日付が明日以降のLIVE（これからの予定）は含めない（`isFutureRec`）。
  - `ticketUrl`：オンラインチケットのURL（`safeWebUrl()` で http(s) のみ）。フォームでは「チケット代」の上に入力欄があり、一覧の「…」メニューに「チケットを見る」を出す。
  - `streamUrls`：配信URLの配列（http(s) のみ）。互換のため1件目は `streamUrl` にも入れる。以前の記録は `streamUrl` だけでも表示できる（`recStreamUrls()`）。一覧の「…」メニューに「配信を見る」を出す（複数なら（1）（2）…とドメイン）。
  - `venuePlace`：会場を Google マップの候補から選んだときの場所 `{ placeId, name, address, lat, lng }`。手入力のままなら `null`（遠征マップ用）。
  - `extraOshis`：対バンなどで一緒に記録する2人目以降の推し `[{ oshiId, groupId }]`。1人目は従来どおり `oshiId` / `groupId`。
  - 推し別の集計（参戦回数・金額）では、`recHasOshi()` で `oshiId` と `extraOshis` の両方を対象にし、金額は `recAmountForOshi()` で人数に均等に割ります（合計の二重計上を防ぐため）。
  - フォームでは推しとグループを横並びで選び、LIVEのみ「＋ 推しを追加」で行を増やせます。LIVEの行は「人物名・グループ名・チェキボタン（アイコンの右に「チェキ」）・✕ボタン」の4列（1行目は✕の位置を空けて列をそろえる）。物販の行は「人物名・グループ名・チェキボタン」の3列。
  - チェキボタンを押すと、その行の推し・グループと、LIVEの日付・公演・ツアー名で、チェキの記録（1枚・金額0）をすぐに追加します。物販では、日付と商品名（空ならイベント名・購入先）で追加します。チェキ記録タブでは、物販から来たチェキは商品名で表示します（以前にイベント名・購入先で作ったものは、同じ日付・同じ名前・同じ推しの物販が1つに決まればその商品名）。
- cheki固有: `title, count, price, content, photo`
- goods固有: `title, item, price, qty, photo, shopUrl`（`shopUrl` はONLINE物販のURL。`safeWebUrl()` で http(s) のみ保存し、一覧に「購入ページを見る」リンクを表示）（写真はLIVEと同じくチケット右側の背景に表示）

## 実装上の注意点（引き継ぎ時に踏みやすい罠）

1. **CSS詳細度の罠**：`.field input[type=text], .field select, ...` という汎用ルール（`width:100%` 等を強制）が、コンポーネント個別のスタイル（例：グループカード内の小さな名前入力欄）より詳細度で勝ってしまうことが何度か発生しました。フォーム内に新しい `input`/`select` を独自スタイルで追加する場合は、汎用ルールの詳細度（`.field input[type=xxx]` は2クラス+属性セレクタ）を上回るように `!important` を使うか、汎用ルールに含まれない要素構造にすることを推奨します。
2. **ポップオーバーの位置**：SNSアイコン編集・カラーピッカー・トップバーのドロップダウンなど、すべて `position:fixed` ＋ `openPopoverNear(anchorEl, popEl)` で位置計算しています。横スクロールするコンテナの中に絶対配置のポップオーバーを置くと親のスクロールで表示がズレる問題が過去にあったため、この方式に統一しています。
3. **画像形式**：ロゴなど透過を保持したい画像は必ず `resizeImageFilePreserveAlpha`（PNG出力）を使うこと。既存の `resizeImageFile` はJPEG出力のため透過が失われます。
4. **`/mnt/user-data/outputs/` との同期ズレ**：作業用ファイルと公開用ファイルを手動 `cp` で同期する運用だったため、一度だけ同期漏れによる巻き戻りバグが発生したことがあります。Claude Codeでの開発では、Gitなど単一の真実源で管理することを推奨します。
5. **推しリスト・グループリストの並び順**：`state.oshis` 配列そのものの並びが表示順＝優先順位（先頭が「メイン」）です。別途ソート用フィールドはありません。ドラッグ＆ドロップ・矢印ボタンでの並べ替えはどちらも配列を直接 `splice` して並べ替えています。

## 主な機能一覧

- 複数推し・推しごとの複数グループ（兼任）管理、グループごとのSNS・担当カラー
- LIVE／チェキ／物販の記録（写真、配信URL、チケット情報など）
  - 写真の欄を押すと「写真を撮る」（カメラ）「写真を選ぶ」（端末の写真）を選べる。撮った・選んだ写真はそのまま入る。チェキは「枚数」を入力でき、写真も複数枚登録できる（`photos` 配列。容量を抑えるため `photo` には入れない。以前の1枚だけの記録は `photo` のまま読む＝`recPhotos`）。写真欄の「追加」から撮る・選ぶ（複数選択可）、各写真を押すと拡大・編集（枠合わせ・明るさなど）・削除。写真の数が枚数より多ければ枚数を合わせる。
  - 記録一覧で写真を拡大するには、LIVE・物販は右下の拡大ボタン、チェキはチェキ写真を押す。
- LIVE記録タブは、チケットの上にカレンダー（`liveCalendarHtml`）を出す。はじめは今月で、‹ › で月を移る。LIVEのある日はマスの背景に写真を入れて示し（LIVEの写真 → 推しの写真 → LIVEのアイコンの順）、同じ日に2件以上あれば件数を出す。今日は枠で示す。チェキのカレンダー表示も同じ見た目（推しの色になじむカードの色・正方形のマス・背景の写真はチェキの写真 → 推しの写真 → アイコンの順・今日の枠・件数）で、共通の `calHeadHtml` / `calDayCellHtml` を使う。日を押すとその日のLIVEだけを下に並べ、もう一度押すか「すべて表示」で元に戻る。
- カレンダーの週の始まり：マイページのアカウントのカード「Googleカレンダー」の下の「週の始まり」で日曜・月曜・土曜から選ぶ（設定 `weekStart` として同期。日曜のときは設定行にキーを持たせない）。LIVE記録・チェキ・集計のカレンダーすべてに使う（`weekDayLabels` / `leadingBlankDays`）。
- 記録の写真（LIVE・チェキ・物販 共通。`recordPhotosFieldHtml`）：複数枚を並べ、＋で追加（撮る・選ぶ。複数可）。写真を押したまま動かすと並べ替えられ（指の下の写真の位置へ）、写真を押すと「拡大して見る」「1枚目にする」「写真を編集する」（チェキのみ）「写真を削除」。1枚目に「表示」の印を付け、一覧・カレンダーなどには1枚目を表示する。LIVE・物販は `photos`（並び順）と `photo`（＝1枚目）を持ち、チェキは `photos` だけを持つ（1枚ごとのお気に入り `favs` も並べ替えに合わせて動かす）。保存時は3枚ずつ同時にドライブへ送る。
- チェキ記録タブの表示（`chekiPageHtml`）：上にカレンダー（`chekiCalendarHtml`）、下にスワイプ（`chekiSwipeHtml`）。カレンダーの日を押すと、その日のチェキだけをスワイプに並べる（もう一度押すか「すべて表示」で元に戻る。`state.chekiCalDate`）。はじめはいちばん新しいチェキの月。以前のマイページ「チェキの表示」（5種類から選ぶ設定 `chekiView`）は廃止した。
  - 共通：上に「★（お気に入り。ON/OFFの切り替え）・すべて・人物名」の絞り込み、その下に「総枚数・今月」。金額と枚数（×2 など）は表示しない。1件の記録に枚数・写真が複数あっても、一覧では1枚ずつのカードに分けて表示する（`chekiUnitList`。枚数は「枚数」の欄と写真の数の多いほう＝`chekiUnits`）。★（お気に入り）は1枚ごとに `favs` に持つ（`favorite` はどれか1枚でもお気に入りなら true）。写真を押すと拡大、写真がなければ押すと編集。各チェキの左上にLIVE・物販一覧と同じスタンプ（アイコン＋「LIVE」「物販」。どちらから来たチェキか）、右上に★（押すたびにお気に入りON/OFF）、右下に鉛筆（編集）。LIVE・物販のチェキボタンで作ったチェキは `source`（`live` / `goods`）を持ち、それ以前のものは同じ日付・同じ名前・同じ推しのLIVE（なければ物販）から判定する。
  - カレンダー：LIVE記録と同じ見た目（`calHeadHtml` / `calDayCellHtml`）。マスの背景はチェキの写真 → 推しの写真 → アイコン。
  - スワイプ：大きなチェキを左右にスワイプしてめくる。下に「何枚目 / 全体」。
  - 集計タブのカレンダーで日付を選んだときの一覧は、LIVE・物販と同じチケット型のまま。
- 統計（推し別／イベント別／期間別／カレンダー）

## 会場と Google マップ（遠征マップの準備）

LIVE の「会場」欄の右の「探す」ボタン（または Enter）で、入力した会場名を Google マップで検索します（Places API (New) のテキスト検索 `Place.searchByText`、最大5件）。結果から選ぶと正式名称・住所・緯度経度・Place ID を `venuePlace` に保存し、遠征マップでもその位置を使います。会場名を手で書き換えると `venuePlace` は外れます。APIキーが無いとき（または Google マップが使えないとき）は、「探す」は OpenStreetMap（Nominatim）で検索します（「座標の取得」の回数に数える）。

- 会場名は、記録一覧で Google マップへのリンクになります（APIキー不要の検索URL）。
- APIキーは Vercel の環境変数 `GOOGLE_MAPS_API_KEY` に設定し、`/api/config` の `googleMapsApiKey` でブラウザに渡します。キーが無いときは OpenStreetMap で検索します。
- Google Cloud で有効にする API：**Maps JavaScript API**、**Places API (New)**。キーは「HTTPリファラー」を `https://oshikatsu-diary.vercel.app/*` に制限し、API の制限もこの2つにしてください。
- 今後「遠征マップ」を作るときは、`state.live` の `venuePlace.lat / lng` を使います。

## アプリとしてインストール（PWA）

- `manifest.webmanifest`：アプリ名・アイコン・`display: standalone` など。`icons/` にアイコン（192/512、maskable 512、apple-touch-icon 180、favicon 32）。
- `sw.js`：Service Worker。画面（HTML）はネットワーク優先で、つながらないときだけ保存済みを表示。静的ファイルはキャッシュ優先で裏で更新。`/api/` と外部サービス（Supabase・Google など）はキャッシュしない。内容を大きく変えたときは `CACHE` の名前（`oshikatsu-v1`）を上げると古いキャッシュが消える。
- `index.html` で https（と開発用の localhost）のときだけ Service Worker を登録する。ブラウザのステータスバー色（`theme-color`）はテーマに合わせて変わる。
- Android の Chrome：メニュー →「ホーム画面に追加」→「インストール」。iPhone の Safari：共有 →「ホーム画面に追加」。

## ホームのカードの並べ替え

ホームの「ギャラリー」「遠征マップ」「月別 推し活費用」は、各カードの上の中央にあるつまみ（点6つ）を押したまま上下に動かして並べ替えられる（`bindHomeReorder` → 共通の `bindDragReorder`。推しの管理ページも同じ操作）。指でもマウスでも動くよう Pointer Events を使い、となりのカードの真ん中を越えたら入れ替わる。並び順は設定 `homeOrder`（`["gallery","map","chart"]` の順番）として同期する（標準の並びのときは設定行にキーを持たせない）。推しのカードは常に一番上。

## ギャラリー（ホーム）

ホームの推しのカードの下に、お気に入りの推しの写真を横にスワイプして見る「ギャラリー」を置く（`galleryHtml` / `bindGallery`）。写真は推しの `gallery`（写真の配列。新しい順）に持つ。

- 写真1枚の大きさは枚数に関係なく 240×300px で固定（写真が無いときの「推しの写真を追加」も高さ300px）。
- 表示の並びはアプリを開くたびにシャッフルする（`galleryOrder`）。開いている間は並びを保ち、追加した写真はその場で先頭に出す。写真は全体が見えるように枠に収め、余白は同じ写真をぼかして埋める。
- 選んだ写真はすぐにギャラリーの先頭に「保存中…」として出し（端末の画像をそのまま表示。記録には入れない）、裏で3枚ずつ同時に縮小してドライブへ送る（`addGalleryFiles` / `resizeImageToBlob` / `DrivePhotos.uploadBlob`）。1枚送れるごとに記録へ入れて同期を始める。
- 「＋ 追加」から「写真を撮る」「写真を選ぶ」（複数可）。長辺1080pxに縮めて保存する。右上に「何枚目 / 全体」。写真を押すと拡大、写真の右上の×でギャラリーから外す（ドライブのファイルは消さない）。
- Google ドライブに接続していれば、追加した時点でドライブへ保存し、`gallery` には `gdrive:<ファイルID>` だけを入れる。ドライブの設定があって未接続なら、写真を選ぶ前に接続を求める。送れなかった写真や、ドライブの設定前に追加した写真は、接続中に自動でドライブへ移す（`DrivePhotos.migrate`）。
- 推しの編集画面で保存しても `gallery` はそのまま引き継ぐ。

## 遠征マップ（ホーム）

ホームの推しのカードの下（月別 推し活費用の上）に、お気に入りの推しの「現地」LIVEの会場を地図にピンで表示する（`TripMap`）。ホームの推しのカードには「参戦回数・チェキ枚数・物販点数」の欄と推しの切り替えボタンの列を出さない（推しの切り替え・追加・管理は上部のドロップダウンから）。

- 地図は Leaflet 1.9.4（`vendor/leaflet/` に同梱）＋ 国土地理院の淡色地図タイル（`cyberjapandata.gsi.go.jp/xyz/pale`、APIキー不要、出典表示「国土地理院」）。タイルには少しセピアをかけて紙の色味に合わせる。（CARTO はAPIキー必須になったため使わない）
- 位置は、会場を候補から選んだときの `venuePlace.lat/lng` を優先。無いときは会場名を OpenStreetMap の Nominatim で検索し、結果を端末の `localStorage`（`oshikatsu_geo_v1`）に保存する。検索は1秒に1件まで、見つからなかった会場は7日間は再検索しない。見つからないときは「(TOKYO)」のような括弧書きを外した名前でもう一度調べる。ほかの推しの記録で候補から選んだ会場と同じ名前なら、その位置を使う。
- 地図の画像（タイル）が読み込めなかったマスは、少し待って2回まで取り直す。枠の大きさが変わったら `ResizeObserver` で地図の大きさを合わせ直す。
- ピンはテーマカラーのしずく型で、中に回数を表示（3回以上は大きめ）。押すとテーマカラーの見出し付きの吹き出しで会場名・回数・公演の一覧を表示。
- カード上部に「VENUES（会場数）」「現地参戦（回数）」、地図の下に会場チップ（回数の多い順、横スクロール）。チップを押すとその会場へ移動して吹き出しを開く。位置が分からない会場のチップは薄く表示し、押すとその会場のいちばん新しいLIVEの編集画面を開く（「探す」で会場を選び直せる）。選び直して会場名が変わったときは、元の会場名のままの位置が分からない記録もまとめて同じ会場にするか確認する。
- 表示範囲の自動調整はアニメーションなし（ホームの再描画で地図を作り直しても落ちないように）。
- 配信で観たLIVE（`viewing: "stream"`）と非表示の記録は含めない。
- 現在地：地図右上の現在地ボタンで `navigator.geolocation` から取得し、青い点で表示。会場チップと吹き出しに現在地からの距離を出す。現在地はその画面の中だけで使い、保存も送信もしない。
- 距離で絞る：地図の上の「すべて / 3km / 10km / 30km」。現在地から半径内の会場だけをピン・チップ・件数に出し、半径の円を点線で描く（現在地が未取得なら先に取得する）。
- 地図の操作（右上のボタン）：「ピンを中央に」（表示中のピンと半径の円に表示範囲を合わせる）、「現在地」。地図を指で動かした後は、会場の位置が分かっても表示範囲を勝手に戻さない。

## 記録を失わないための仕組み

- **削除しても中身を残す**：記録を削除すると、クラウドには中身を残したまま `deleted: true` を送る（`rememberDeleted` → `cloud.tomb`）。クラウド側のトリガーでも、中身が空の削除は直前の中身を残す。
- **一度に大量の削除を止める**：1回の同期で4件以上削除しようとしたら、送る前に確認する（`CLOUD_MASS_DELETE`）。「キャンセル」なら削除せず、クラウドから全件を取り直す。
- **変更履歴**：`supabase/migrations/20260927000000_oshikatsu_records_history.sql`。記録が上書き・削除される直前の内容を `oshikatsu_records_history` に自動で残す（30日で消える）。アプリからは本人の履歴を読むことだけができる。**Supabase の SQL Editor でこのファイルを1回実行する。**
- **マイページの配置**：アカウントのカードは「Google認証」「メールアドレス」「パスワード」「Googleドライブ（接続）」「Googleカレンダー（登録ルールの設定。シートで開く）」「週の始まり」「バックアップ（最終日時・毎日自動・保存／戻す）」の順。右のボタンは同じ横幅（60px）。カードの下に「ファイルに保存」「ファイルから戻す」「削除された記録を探す」のリンクを置く。Google ドライブが未設定（`GOOGLE_OAUTH_CLIENT_ID` なし）の間は、ドライブの行のボタンは押せない。
- **復元**：マイページの「削除された記録を探す」で、クラウドの削除済みの記録と変更履歴から、今ない記録を探して戻す。
- **ファイルに保存**：「全データをファイルに保存」で JSON を保存（写真は Google ドライブのファイルIDか画像データ）。「ファイルから戻す」は、今ない記録（同じIDが無いもの）だけを加え、今ある記録は変更しない。
- **Google ドライブに保存**：Google ドライブの設定（`GOOGLE_OAUTH_CLIENT_ID`）があれば、「Googleドライブに保存」で同じ JSON を「推し活手帳」フォルダに `oshikatsu-backup-YYYYMMDD-HHMM.json` として保存し、「Googleドライブから戻す」で一覧から選んで戻す（今ない記録だけを加える）。接続中は1日1回自動で保存し、新しい14件だけを残す（`DrivePhotos.autoBackup`）。

## 写真の保存先（Google ドライブ）

画像はすべて本人の Google ドライブの「推し活手帳」フォルダに保存し、記録には `gdrive:<ファイルID>` だけを入れる（`DrivePhotos`）。対象は LIVE・チェキ・物販の写真、ホームのギャラリーの写真、推しの写真（切り抜き後 `photo` と元の写真 `photoOriginal`）、ヘッダーロゴ（設定 `headerLogo`）。Supabase には画像データを持たない。推しの写真・ヘッダーロゴを選ぶ前にもドライブへの接続を求め、以前から記録の中にある画像データは、接続中に自動でドライブへ移す（`DrivePhotos.migrate`）。

- **フォルダ分け**：「推し活手帳」の中を「Backup」「LIVE」「チェキ」「物販」「Gallery」「その他」に分け、ファイル名で振り分けて保存する（`subFor`：`oshikatsu-backup-` → Backup、`live_` → LIVE、`cheki_` → チェキ、`goods_` → 物販、`gallery_`（ホームのギャラリー） → Gallery、推しの写真・ヘッダーロゴなど → その他）。フォルダの作成は同時に呼ばれても1回にまとめる（重複フォルダを作らない）。
- **自動の振り分け**：接続中は1日1回（写真をドライブへ移し終えたあと）、振り分け前のファイルを各フォルダへ自動で移す（`DrivePhotos.autoSort`。ゴミ箱へは移さない）。
- **整理**：マイページのアカウントのカード「Googleドライブ」が接続中のときの「整理」ボタン（`organizeDrive` → `DrivePhotos.planOrganize` / `runOrganize`）。先に同期してから、(1) 「推し活手帳」が複数あればいちばん古いものにまとめ、空になったものをゴミ箱へ、(2) 振り分け前のファイルを各フォルダへ移し、(3) どの記録にも使われていない写真（2台で同時に移したときなどにできる重複）をゴミ箱へ移す。作って1時間以内の写真は、別の端末の記録がまだ届いていないことがあるので残す。実行前に件数を確認のダイアログで示す。ゴミ箱のファイルは Google ドライブから30日以内なら戻せる。
- **Supabase に残った画像データの削除**：`supabase/migrations/20260928010000_oshikatsu_strip_images.sql` を SQL Editor で実行すると、変更履歴（`oshikatsu_records_history`）と削除済みの記録に残る画像データを null に置き換え、以後は変更履歴に残すときも画像データを消す（`oshikatsu_strip_images`）。表示中の記録の画像データは、アプリがドライブへ移して置き場所に書き換える。

- 権限は `https://www.googleapis.com/auth/drive.file`（このアプリが作ったファイルだけ）。ログインとは別に Google Identity Services のトークン（約1時間）をもらい、`localStorage`（`oshikatsu_gdrive_token_v1`）に期限付きで置く。
- **接続を続ける（推奨）**：Vercel に `GOOGLE_OAUTH_CLIENT_SECRET` があると（`/api/config` の `googleDriveServer: true`）、接続は認可コード方式（`initCodeClient`）になる。受け取ったコードを `/api/gdrive-token`（`exchange`）でトークンに交換し、リフレッシュトークンを Supabase の `oshikatsu_gdrive_tokens`（本人の行だけ読み書きできる。`supabase/migrations/20260928000000_oshikatsu_gdrive_tokens.sql`）に保存する。アクセストークンが切れたら `refresh` で新しいものをもらうので、つなぎ直しは不要。同じアカウントでログインしていれば、別の端末（PC・スマホ）でもつなぎ直さずに「接続中」になる（起動後に一度 `refresh` で確かめる）。Google 側で許可が外されたときは保存したトークンを消し、「再接続が必要」に戻る。サーバーへの呼び出しにはログイン中の Supabase のトークンが必要で、クライアントシークレットはサーバーの中だけで使う。シークレットが無いときは、これまでどおり1時間ごとにつなぎ直す方式で動く。
- Google Auth Platform の公開ステータスが「テスト」のままだと、リフレッシュトークンは7日で失効する。`drive.file` は機密性の低いスコープなので、「本番環境に公開」しても審査は不要。
- 未保存の写真を作らないよう、ドライブの設定があるときは、写真を撮る・選ぶ前に接続を求め（`requireConnection`）、記録を保存した時点で写真をドライブへ送る（`uploadNow`）。通信の失敗などで送れなかった写真と、以前の写真は、接続中に自動でドライブへ移す（`migrate`）。
- 表示した写真は端末の IndexedDB（`oshikatsu_photos`）に覚え、2回目からは通信しない。端末に無く、トークンも切れているときは、画面下に「Googleドライブの写真を表示する」を出し、押すと接続して表示し直す。
- 別の端末でも同じ Google アカウントで接続すれば表示できる（drive.file は、そのアカウントでこのアプリが作ったファイルにだけアクセスできる）。
- ドライブのフォルダやファイルを削除すると、アプリから写真が見えなくなる。記録を削除してもドライブのファイルは消さない。
- 設定：Vercel の環境変数 `GOOGLE_OAUTH_CLIENT_ID`（ウェブアプリの OAuth クライアントID）と、接続を続けるための `GOOGLE_OAUTH_CLIENT_SECRET`（同じクライアントのシークレット。サーバーだけで使い、ブラウザへは返さない）。シークレットを使うときは、Supabase の SQL Editor で `20260928000000_oshikatsu_gdrive_tokens.sql` を実行しておく。未設定なら「写真の保存先」は出ず、写真は記録の中に持つ。Google Cloud で Google Drive API を有効にし、OAuth 同意画面に `drive.file` を追加し、OAuth クライアントの「承認済みの JavaScript 生成元」に `https://oshikatsu-diary.vercel.app` を入れる。

## 端末の控え（キャッシュ）が保存できないとき

ログイン中はクラウドが正本で、端末の `localStorage`（`oshikatsu_diary_v1:u:<uid>`）には控えを置く。写真が増えて容量（約5MB）を超えると控えが保存できない。古い控えが残ったまま次に開くと、その古い内容がクラウドへ送り返されて新しい記録や写真を上書き・削除してしまうため、`writeCache()` は保存に失敗したら古い控えを消し、同期の記録（`oshikatsu_sync_v1:<uid>` の hashes / lastPulledAt）も空にする（`cloud.cacheStale`）。起動時も、控えが無いのに同期の記録だけあるときは使わない。次に開いたときはクラウドから全部取り直す。

## 費用の歯止め（1日あたりの利用上限）

`UsageLimit` が端末ごとに1日あたりの回数を `localStorage`（`oshikatsu_usage_v1`、日付が変わるとリセット）で数え、上限に達したらその機能を止めて案内を出す。Google Cloud 側の割り当て上限（Quotas）と二段構えで使う。

| 種類 | 上限/日 | 数えるもの | 上限に達したとき |
|---|---|---|---|
| 地図の読み込み（`mapLoad`） | 200回 | 遠征マップを作るたび | 地図を作らず、枠内に案内を表示 |
| 座標の取得（`geocode`） | 100回 | Nominatim の会場検索（遠征マップの自動検索と、APIキーが無いときの「探す」） | 残りの会場は翌日に調べる |
| 会場の検索（`placeSearch`） | 50回 | 「探す」ボタンでの Google マップ検索（`Place.searchByText`） | 検索せず、トーストで1回だけ案内 |

Google Cloud コンソールの「APIとサービス → 割り当て」でも、Maps JavaScript API・Places API (New) の1日あたりの上限を設定してください。

## アカウントの種類と機能のON/OFF（ユーザー管理）

アカウントは「マスター」「有料」「無料」の3種類（Supabase の `oshikatsu_profiles.plan`。`supabase/migrations/20260928020000_oshikatsu_plans.sql`）。新しく登録した人は自動で「無料」になる。本人は自分の種類を読めるだけで変更できず、変更できるのはマスターだけ（行レベルセキュリティと `oshikatsu_is_master()`）。最初のマスターは、SQL の最後の1行（メールアドレスを入れる）で決める。

- マイページのログアウトの上に「ユーザー管理」（マスターだけに表示。`state.view = "admin"`、`renderAdminPage`）。
  - 機能の設定：有料・無料それぞれについて、機能ごとにスイッチでON/OFF（`oshikatsu_plan_features`。行が無い機能はON）。マスターは常にすべて使える。
  - ユーザー：全員のメールアドレスと種類。種類を選ぶとその場で変更（マスターが1人もいなくなる変更はできない）。
- マイページの「アプリ課金」（`billingSectionHtml`。アカウントのカードの下）：現在のプラン、有料プランの料金、次回の更新日・お支払い方法（有料のとき）、「有料プランにする」（無料のとき）／「お支払いの管理」「解約する」（有料のとき）、有料プランだけで使える機能の一覧（有料ON・無料OFFの機能）、特定商取引法に基づく表記へのリンク。決済は Stripe を予定しており、未定の値は「●●●」（`BILLING_TBD`）で表示し、ボタンは「準備中」と表示するだけ。
- マスターだけ、マイページのタイトルの右に「マスター／有料／無料」の切り替え（`planPreviewSwitchHtml`）。選んだプランの見た目と機能のON/OFFで画面を表示して確認できる（`effectivePlan`。そのタブを開いている間だけ `sessionStorage` に覚える。データや権限は変えない）。切り替え中は画面の上に「○○の表示を確認中」と「マスターに戻す」を出す。ユーザー管理の書き込みは本当のマスター（`realMaster`）だけ。
- ON/OFFできる機能（`PLAN_FEATURES`）：チェキ記録・物販記録・集計（タブを隠す）、ホームのギャラリー・遠征マップ・月別 推し活費用、写真の登録（欄を隠す。登録済みの写真は残る）、写真を複数登録（1件1枚まで）、推しを複数登録（2人目から登録できない）、Googleカレンダーに追加、バックアップ（ドライブ・ファイル。毎日の自動保存も止める）、削除された記録を探す。
- 判定は `canUse(機能)`。種類と設定はログイン時に読み込み、端末に控える（`oshikatsu_access_v1:<ユーザーID>`）。表が無い（SQL未実行）ときや読み込めないときは、すべて使える。機能を隠すのは画面の上だけ。
- ユーザーの一覧は、マスター → 有料 → 無料 の順に並ぶ（同じ種類の中は登録順）。上の「すべて・マスター・有料・無料」（人数つき）で種類を絞り込める（`adminFilter`）。

## NEWS（お知らせ）

マイページの一番上に、すべてのプラン（マスター・有料・無料）でお知らせを新しい順に出す（`newsSectionHtml`。お知らせが無いときも欄を出し「お知らせはまだありません。」。はじめは3件、「すべて見る」で全部。題名を押すと本文を開く。7日以内のものに NEW）。お知らせは Supabase の `oshikatsu_news`（だれでも読める。追加・編集・削除はマスターだけ。`20260928020000_oshikatsu_plans.sql` に含む）。マスターは「＋ お知らせを追加」から日付・題名・本文を入れて公開し、各お知らせの「編集」「削除」で直せる。まだ見ていないお知らせがあると、マイページのタブに赤い印を付ける（見た時点を端末に覚える）。

## セットリスト（LIVE）

LIVE記録の入力画面は、上の「LIVE記録を編集／セトリ記録を編集」で切り替える（入力が多くなるため、セットリストは別の画面。`rec-pane-tab`。どちらの画面で保存しても両方保存する。LIVEの必須の欄が空のまま保存するとLIVEの画面に戻る）。セトリ記録の画面の「セットリスト（任意）」（`setlistFieldHtml` / `bindSetlistField`）で、対バンを考えて出演アーティストごとに分けて入れる。

- 「＋ アーティストを追加（対バン）」で枠を足す。名前はこのLIVEの出演グループ（グループのない推しは人物名）から、まだ使っていないものを順に入れる。▲▼で出演順を入れ替え、×で枠ごと削除。
- 曲の追加（`bindSetlistField`）：枠の下の入力欄に曲名を入れてEnter（または「追加」）で追加し、欄は空になってそのまま次の曲を打てる。入力欄の下の候補（何も打っていなければ、そのアーティストの曲でまだ入れていないもの。打つと曲名・アーティスト名で探した登録済みの曲）を押しても追加できる。虫めがねは「曲を探す」（登録済みの曲から選ぶ・新しく登録）。
- 「曲のアーティスト」（入力欄の上。初期値は出演アーティスト）：押すとアーティストを検索して選べ（`openArtistPicker`。Enterで先頭の候補、無ければ新しいアーティストとして使う）、候補はそのアーティストの曲だけになり、追加した曲はそのアーティストの曲になる。「出演アーティストに戻す」で元に戻す。ほかのアーティストの曲を続けて入れるときに、曲名とアーティスト名を行き来せずに済む。
- 曲は「曲名／アーティスト名」で登録する（ほかのアーティストの曲を歌うこともあるため）。入力欄に「曲名／アーティスト名」と入れればアーティストも分かれ、空なら出演アーティストの曲（`songArtist`。保存時、出演アーティストと同じなら持たない）。表示・コピーは「曲名／アーティスト名」。
- 追加した曲・MC・SEは1行ずつコンパクトに並び（曲は番号、MC・SEは番号なし）、行を押すとその行だけ入力欄になって直せる（✓またはEnterで決定、×で削除）。並べ替えは、左のつまみを押したまま上下に動かすか、スマホでは行を0.35秒長押ししてから動かす（先に指が動いたときは画面のスクロール）。動かしている間はほかの行がよけて入る位置を見せ、画面の上下の端に向かって動かすと自動でスクロールする（`beginDrag`）。「＋ MC」「＋ SE」で追加し、メモ（任意）を入れる。MC・SE（登場曲・転換などの音源）は曲数に数えない。
- 「まとめて入力」で複数行を入れて（貼り付けて）「取り込む」。入力欄に複数行を貼り付けても取り込む。行頭の番号（「1.」「M1」「EN1」など）は外し、「MC」「SE」で始まる行はMC・SE、「曲名／アーティスト名」の行はアーティストも分ける（`parseSetlistLine`）。
- 入力欄に打ったまま「追加」していない曲も、保存するときに入れる。
- 入力候補（同じアカウントのどの端末でも同じ。推しの所属・グループ名と同じ仕組み）：アーティスト名は推しのグループ・人物名と、登録済みのセットリストのアーティスト（`setlistArtistOptions`）。曲名は、登録済みの曲（そのアーティストの曲を先に。`setlistSongOptions`）。
- 記録には `setlists = [{artist, items:[{t:"song", title, artist?} | {t:"mc", note} | {t:"se", note}]}]` として持つ。以前の `setlist`（曲名の配列）は、そのLIVEのグループを1組目として読み替え（`recSetlists`）、保存したときに `setlists` へ移す。
- 一覧のLIVEの「…」メニューにいつも出す：登録済みなら「セットリスト（N組・N曲）」で一覧（アーティストごと。「コピー」「編集する」）、未登録なら「セットリストを登録」で編集画面を「セトリ記録を編集」で開き、1組目と1曲目を用意する（`openSetlistEditor`）。
- プランの機能のON/OFFの「セットリスト」がOFFのときは、欄とメニューを隠し、登録済みのものは残す。

## 音楽アプリで聴く

曲の「聴く」ボタン（再生の丸いアイコン）から、音楽アプリの検索結果（曲名＋アーティスト名）を開く（`openListen`）。ログインやAPIの登録は不要で、スマホにアプリが入っていればアプリで開く。

- ボタンがある場所：LIVEの「セットリスト」を見る画面の各曲、アーティストの画面の曲のランキング（行の本体を押すと今までどおり曲の編集）。
- 対応アプリ（`MUSIC_APPS`）：Amazon Music・Spotify・Apple Music・YouTube Music・YouTube。
- マイページのアカウントの「音楽アプリ」の「変更」で、出すアプリを選ぶ（いくつでも。`openMusicAppsSheet`）。1つだけのときは押すとすぐ開き、2つ以上のときは開くアプリを選ぶ画面を出す。何も選ばないと「聴く」ボタンを出さない。
- 選んだアプリは設定 `musicApps`（アプリのIDの配列。未設定 = すべて）として同期する。プランの機能の「セットリスト」がOFFのときは、この項目も隠す。

## アーティスト・曲の登録一覧（マイページ）

マイページの「アーティスト・曲の登録一覧」（`catalogEntryHtml` → `state.view = "catalog"`、`renderCatalogPage`）。

- アーティストの一覧：上に「組・曲・回歌唱」の合計、下に2列のタイル（曲数・歌った回数）。タイルは横3：縦2（宣材写真の一般的な比率。同じ比率の画像は切れずに全体が入る）。タイルは推しのグループの色（`catalogArtistColor`）のグラデーション、背景画像を設定したアーティストはその画像。曲がまだ無いアーティストは白いタイル。上の欄で検索し、同じ名前が無ければ「＋ 「○○」をアーティストとして登録」。押すとそのアーティストの画面へ。
- アーティストの画面：上は推しカラーのアルバムジャケット風の見出し（曲数・歌唱回数・LIVE数と「編集」）、下は曲のランキング（「よく歌う順」「あいうえお順」「未使用」で切り替え。`catalogView.sort`。よく歌う順の1〜3位は金・銀・銅、歌った回数は横棒で表示。セットリストで使っていない曲は「未使用」）。上の欄で曲を検索し、無ければ「＋ 「○○」を○○の曲として登録」（Enterでも登録）。
- 見出しの背景画像：見出しの右上のカメラから画像を選ぶと、見出しの背景になる（`bindCatalogHero`）。画像は Google ドライブの「その他」に保存し、アーティストの登録に `image`（`gdrive:` の参照）として持つ。選んだあとに「背景画像の表示位置」の画面が開き、見出しの形の枠で画像をドラッグして見せたい部分を決める（一覧のタイルの見え方も一緒に表示。`openCatalogImagePos`）。位置は `imagePos`（"x% y%"）として持ち、見出しとタイルの両方で使う。決めていない画像は少し上寄り（50% 30%）で表示する。あとから「編集」の「背景画像の表示位置を調整」で直せる。外すときは「編集」の「背景画像を外す」。ドライブの整理では使っている画像として残す（`referencedIds`）。
- 変更・削除：見出しの「編集」でアーティスト名の変更・削除（`openCatalogArtistSheet`）、曲を押すと曲名・アーティストの変更・削除（`openCatalogSongSheet`）。曲のアーティストは、押すと開く一覧から選ぶ（検索・新しい名前もここで。`openArtistPicker`）。
  - 変更はLIVE記録のセトリにも反映する（`renameCatalogArtist` / `editCatalogSong`、`eachSetlistRec`）。すでにある名前にすると1つにまとまる（`dedupeCatalog`）。推しのグループ名と同じアーティストの名前を変えると、推しのグループ名も変わる。
  - 削除は、確認のうえLIVE記録のセトリからも取り除く（アーティストは、その出演と曲をまとめて）。推しのグループ名のアーティストは一覧には残り、グループのない推しの人物名は推しの編集から直す。
- 一覧には、登録したもの（`state.artists` / `state.songs`）に加えて、推しのグループ（グループのない推しは人物名）とセットリストで使ったアーティスト・曲も出す。登録した曲はセットリストの入力候補と「曲を探す」にも出る（歌った回数 0回）。「曲を探す」で新しく登録した曲もここに入る（`registerSong`）。
- 登録は記録の表に `kind: "artist"` / `"song"` の行として同期する（`supabase/migrations/20260928030000_oshikatsu_catalog_kinds.sql` で kind を追加）。SQLを実行するまでは、クラウドが受け付けないので送らずに端末に残し（`cloud.catalogUnsupported`）、ほかの記録の同期は止めない。実行後に開くと送る。
- プランの機能の「セットリスト」がOFFのときは、この項目も隠す。
